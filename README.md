# Fling — Flutter app

Native mobile client for the same Fling backend the web app (`fling-web-app`) talks to — same REST API, same Socket.IO real-time layer, same dark pink/purple theme. Built to run alongside the web app, not replace it.

## Setup

This project ships as `pubspec.yaml` + `lib/` only — no `android/`/`ios/` platform folders, since those need to be generated by the Flutter CLI itself (they're mostly binary/UUID-keyed project files that aren't meant to be hand-authored). You'll need the Flutter SDK installed locally.

**Verified:** `flutter analyze` (0 errors), `flutter build web` (passes), and `flutter build apk --debug` (passes — real 156MB APK built) all succeed. The app was also live-tested end to end in a browser — dev-login, Home (real featured-room + wallet-balance data), and Discover all render and function correctly against the live backend, with zero console errors. One real runtime bug was caught this way and fixed: Postgres/Sequelize serializes `DECIMAL`/`SUM()`/`COUNT()` values as JSON strings rather than numbers (e.g. `coinBalance: "10.00"`), which crashed a plain `as num?` cast — every such cast in the codebase now goes through `format.dart`'s `asNum()` helper, which parses either shape.

**Known Android build issue — not fixable from this project:** `agora_rtc_engine`'s bundled native SDK ships two AAR modules (`iris-rtc` and a "full SDK" module) that both declare the Android manifest namespace `io.agora.rtc`. Modern AGP's manifest merger rejects duplicate namespaces outright, and there's no suppression flag for it — confirmed across three different `agora_rtc_engine` versions (6.3.2 / 6.5.4 / 6.6.3) and cross-checked against Agora's own GitHub issues; this is a structural defect in how Agora packages their SDK, not something fixable via `build.gradle`. The Android build with `agora_rtc_engine` temporarily removed compiles clean (proving every other line of app code is Android-buildable) — voice chat is the only thing blocked. Options: wait for Agora to fix their AAR packaging, or swap to a different Agora Flutter wrapper / a different voice-call SDK entirely. The `flutter build web` target is completely unaffected.

Along the way, fixing Android also required (all already applied in this project, for reference if you hit similar issues elsewhere): capping Gradle's JVM heap in `android/gradle.properties` (the Flutter template's default `-Xmx8G` exceeds many real machines' total RAM), overriding `flutter_inappwebview`'s version (the stable release's Android module uses a deprecated ProGuard API modern AGP rejects), and setting `compileSdk`/`rootProject.extra["compileSdkVersion"]` to 36 (several plugins' transitive `androidx` dependencies need 34+, higher than Flutter's own default).

```bash
cd fling-flutter-app
flutter create --project-name fling --org com.yourcompany .
flutter pub get
flutter run
```

`flutter create .` on a directory that already has `lib/` and `pubspec.yaml` fills in the missing platform folders without touching your existing code.

## Architecture

- **`lib/core/`** — `ApiClient` (REST, mirrors the web app's `src/api/client.js` — same base URL, same auth-header/401 handling), `AuthProvider` (token persistence + session state), `SocketService` (Socket.IO connection, same `auth: { token }` handshake as `src/realtime/SocketContext.jsx`).
- **`lib/models/`** — Dart classes mirroring the backend's serialized shapes (`User`, `DiscoverProfile`, `Post`, `Playlist`, `Song`, etc.)
- **`lib/theme/`** — color tokens copied 1:1 from the web app's `src/index.css` `@theme` block. Keep the two in sync if either changes.
- **`lib/screens/`** — one folder per feature area, same split as the web app's `src/pages/`.

The party/room real-time sync (`lib/screens/party/room_socket_controller.dart`) is a direct port of `src/realtime/useRoomSocket.js` — same event names, same payload shapes, talks to the same `syncHandler.js` on the backend without any server changes.

## What's fully wired

Auth (dev-login), Discover swipe with the flip-card detail view, Home, Feed (post/like/comment/save), Profile (bio/gallery/playlists/history/liked/saved, edit form), other-user profiles (follow/friend/DM/block/report), Messages (list + real-time thread), watch-party rooms (YouTube sync, host-controlled play/pause/seek/skip, reorderable queue with search/liked/history/playlist tabs, chat, roster with kick/make-host), voice chat scaffolding (Agora), Lobby (browse/create/join/invite), notifications bell, Wallet (balance/spin/VIP/cashout/KYC), Communities, Events, Leaderboards, Achievements, Challenges, Friends.

## Known limitations / things to finish

These need your own credentials or platform setup — not something to hand-wire without them:

- **Real phone OTP login** — currently only dev-login works (`lib/screens/auth/login_screen.dart`, `kFirebaseConfigured = false`). Wiring real Firebase phone auth needs `firebase_auth` added to `pubspec.yaml` plus `flutterfire configure` run against your Firebase project.
- **Voice chat** — the Agora integration (`lib/screens/party/voice_chat_controller.dart`) is complete but inert until you set `kAgoraAppId` to your own Agora App ID (safe to ship client-side; the actual access-controlled token is still minted server-side). Also currently blocks the **Android** build specifically — see "Known Android build issue" above.
- **Buying coins** — `lib/screens/wallet/wallet_buy_screen.dart` creates the Razorpay order via the backend but doesn't complete checkout; add the `razorpay_flutter` package and wire its native setup to finish this.
- **Gifting** — the web app's gift-sending modal wasn't ported (scope triage given the size of this port); `POST /wallet/gift` is unused from Flutter.
- **Polls, pinned community messages, referral code UI, top-supporters list** — same triage; the backend endpoints exist, the screens don't yet.
